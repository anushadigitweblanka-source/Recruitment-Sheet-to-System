# documentation/

Written explanations of the system and the work: architecture notes, module descriptions, decisions taken and why, open questions for the mentor, and daily work logs.

- Prefer one Markdown file per topic (e.g. `pipeline-stages.md`, `decisions.md`).
- Record decisions with the date and the reason, so they can be revisited later.
- App-internal docs (code-level README files) stay inside `recruitment-sheet-to-system/`; this folder is for task-level documentation.
